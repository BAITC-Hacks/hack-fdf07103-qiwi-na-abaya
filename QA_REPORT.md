## Дополнительные проверки

- **Пустые данные:** анализ пустого описания заблокирован; пустая форма отклика не отправляется; пропущенный ответ не подменяется выдуманным фактом. Пустой поиск каталога показывает reset и понятное состояние.
- **Валидация URL:** javascript:alert(1) отклонён; тестовый HTTPS URL сохранён. Внешняя ссылка не открывалась. Серверная валидация URL покрыта тестами.
- **Двойные нажатия:** в браузере dblclick анализа, публикации, отправки предложения и принятия. В БД ровно шесть вопросов, одна задача и один отклик. Повторное предложение заменено ссылкой «Посмотреть мой отклик». Ограничения уникальности и версии проверены SQLite-тестами.
- **Refresh:** ответы, preview, опубликованная карточка, мои отклики и решение бизнеса сохраняются.
- **Прямые URL:** команда перенаправляется из редактора бизнеса в каталог; прямой URL неопубликованного черновика даёт «Задача не найдена». Опубликованная карточка и списки открываются напрямую.
- **AI:** npm run ai:check:offline подтверждает обе операции без ключа. Тесты проверяют невалидный JSON, недостаточное число/дубли вопросов, лишние поля, неверные типы, выдуманные evidence, отказ/ошибку HTTP и timeout с fallback. Реальный внешний API заново не вызывался в этом аудите.
- **Scoring:** граничные значения 0/39/40/69/70/89/90/100, веса, пустые/краткие поля и защита от присланного клиентом score покрыты тестами.
- **Recommendations:** пять опубликованных задач, убывающий matchScore 90/90/70/40/15 для DataForge, причины и отдельный readinessScore. Сохранение нулевых совпадений проверено unit tests.
- **Next.js / Prisma:** операции БД и AI остаются server-side; client components вызывают server actions. TypeScript, lint и production build проверяют границы модулей. SQLite-тесты проверяют владение, версии, уникальность, подтверждение и транзакции. Секреты не выводились.
