## Что исправлено при аудите

1. В первом реальном вызове структурирования модель поместила пересказ заголовка в evidence.title. Валидация корректно включила fallback, но это ухудшало показ реального AI. Уточнены prompt и описания полей схемы: evidence.title копирует исходное описание, card.title может содержать краткое название. Повторные проверки обеих операций прошли в режиме openai.
2. Ранее существование цитаты само по себе позволяло привязать к ней выдуманный факт. Теперь для фактических разделов проверяется соответствие источника конкретному полю; в итоговую карточку берётся подтверждённая цитата, а не дополненный моделью пересказ. Добавлены регрессионные тесты на постороннюю цитату и выдуманное количество клиентов рядом с настоящим источником.
3. Пустое поле в валидном AI-ответе больше не стирает явно сообщённые сведения: их восстанавливает deterministic extractor. Неизвестные поля остаются пустыми. Это также покрыто тестом.

Новая инфраструктура и дополнительные продуктовые функции не добавлялись. Семантическая корректность короткого AI-названия и классификации текста не гарантируется схемой: все поля остаются редактируемыми, а публикация требует подтверждения бизнеса. Эвристический рейтинг измеряет заполненность, а не достоверность бизнес-данных.

## Подтверждения проверки

- `npm run check`: typecheck, lint, **54 теста**, production build — успешны после финальных изменений кода.
- `npm run ai:check`: обе операции с реальным API — `openai`, неизвестные навыки пустые.
- `npm run ai:check:offline`: обе операции без ключа — `fallback`, шесть вопросов; `.env` не менялся.
- Unit/integration tests: невалидный JSON, refusal, HTTP-ошибка, timeout, неподтверждённые факты; границы рейтинга 0/39/40/69/70/89/90/100; сортировка и фильтры; публикация с нулевым рейтингом; отклики разных команд и защита от дублей; ручные решения и сохранность других предложений; прогресс/баллы; отдельный matchScore рекомендаций.
- Предыдущий полный браузерный QA, включая двойные нажатия, пустые формы, URL, refresh и прямые переходы: `QA_REPORT.md`.
- Повторная репетиция: 11:53:08–11:55:46 UTC, локальный production server. Три вопроса, AI-структурирование, 20 → 65 → 100, ручная публикация, каталог, DataForge отправляет предложение, бизнес принимает. Refresh сохраняет ACCEPTED; прямой URL показывает «В работе». SQLite подтверждает IN_PROGRESS, score=100 и единственный ACCEPTED Proposal.
- После проверки удалены только новая тестовая задача и её отклик. `npm run db:verify`: 1 бизнес, 5 команд, 5 опубликованных задач, 5 черновиков, 8 предложений; реальные рейтинги 35/55/75/87/95. Специальный `draft-demo-retention` сохранён для выступления.

## Короткий сценарий показа

Откройте бизнес → «Создать задачу». Введите: **Мы теряем клиентов интернет-магазина и хотим понять почему.** Нажмите «Получить уточняющие вопросы».

Используйте подготовленные ответы по соответствующим вопросам. Если AI задаст только три вопроса, остальные сведения внесите в редактируемую карточку:

| Раздел | Подготовленный ответ |
|---|---|
| Пользователи | Маркетолог магазина анализирует причины ухода покупателей. |
| Данные | Есть обезличенная CSV-выгрузка заказов за шесть месяцев. |
| Результат | Отчёт о причинах оттока клиентов и три гипотезы улучшений. |
| Критерии | В отчёте три проверяемые гипотезы, каждая подтверждена данными заказов. |
| Ограничения | Срок две недели, без платных сервисов и персональных данных. |
| Взаимодействие | Координатор проекта проводит рабочий созвон каждую среду. |

Сформируйте карточку, покажите пустые разделы и breakdown. Дополните их, задайте название «Причины оттока покупателей» и навыки «Python, SQL, Data Analysis». Покажите рост рейтинга. Откройте preview, проверьте сведения и подтвердите публикацию в диалоге.

Переключитесь на команду, дождитесь каталога и откройте новую задачу. «Предложить решение»: идея — «Проведём когортный анализ повторных покупок и найдём этапы оттока»; план — «Проверим качество CSV, сравним когорты, подготовим три гипотезы и отчёт»; срок — «2 недели». Ссылка необязательна: вставляйте только настоящий URL своего прототипа. Отправьте и покажите PENDING в «Мои отклики».

Переключитесь на бизнес, дождитесь смены роли, откройте «Предложения». Покажите данные команды, нажмите «Принять» и подтвердите решение. Результат: ACCEPTED, задача «В работе». Если останется время, откройте каталог с сортировкой по готовности и покажите опубликованную задачу 35/100: низкий рейтинг не блокирует участие.
